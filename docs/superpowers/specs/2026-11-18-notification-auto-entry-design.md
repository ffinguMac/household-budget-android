# 알림 기반 자동 기록 + 고정 카테고리 설계

작성일 2026-11-18 · 기준 브랜치 `origin/master` (54a761a)

## 1. 의도

사용자는 가계부를 매일 손으로 적는 것도, 매달 은행 엑셀을 넘기는 것도 귀찮다. 목표는 **아무것도 하지 않아도 결제·입출금이 기록되는 것**이다. 사용자가 하는 일은 처음 한 번 권한을 켜는 것과, 가끔(주 1회 정도) 애매한 거래를 골라주는 것뿐이어야 한다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 은행·결제 앱 알림을 읽어 거래를 자동 등록한다.
- 카테고리를 앱이 정한 고정 목록으로 바꾸고, 사용자 추가/편집 기능을 없앤다.
- 자동 분류는 기기 안에서만 하고, 사용자가 고친 결과를 학습한다.
- 같은 돈이 두 번 기록되지 않는다(충전 ↔ 실제 결제, 같은 알림 재수신).

**비목표 (이번 범위 아님)**
- 엑셀(xlsx) 불러오기. 알림을 놓친 기간 보정용으로 나중에 붙일 수 있다. 조사 결과는 부록 A.
- 외부 AI/서버 분류, 마이데이터 연동.
- SMS 읽기(READ_SMS는 Play 정책상 제한).

**실패 조건 (동작해도 실패로 본다)**
- 같은 결제가 두 번 잡혀 지출이 부풀려진다.
- 거래 내역(알림 원문 포함)이 기기 밖으로 나간다.
- 확인 필요 거래가 줄지 않아 결국 매일 손이 간다.
- 기존 사용자의 거래가 업데이트로 사라지거나 엉뚱한 카테고리로 섞인다.

## 3. 제약

- minSdk 26, Kotlin + Compose + Room(현재 스키마 v6) + WorkManager. 신규 의존성은 피한다.
- 타임존 `Asia/Seoul` 고정(기존 코드와 동일).
- 알림 수신은 `NotificationListenerService`. 사용자가 시스템 설정에서 "알림 접근"을 직접 허용해야 한다. 앱은 설정 화면으로 보내는 버튼과 현재 허용 상태만 보여줄 수 있다.
- 알림 원문은 개인 금융정보다. Room에만 저장하고, 로그(Logcat)에 찍지 않는다. 백업 대상에서 제외할지 여부는 기존 `allowBackup` 설정을 따르되, 빌더가 확인해 보고한다.
- 이 저장소에는 실제 은행 파일·알림 원문을 커밋하지 않는다. 테스트 픽스처는 가짜 데이터로 만든다.

## 4. 접근 방식 (검토한 안)

| 안 | 내용 | 장점 | 단점 | 결정 |
|---|---|---|---|---|
| A. 알림 자동 기록 | 결제/입출금 푸시 알림을 실시간 파싱 | 매일 할 일 0, 실시간 | 알림 문구 변경에 취약, 알림 접근 권한 필요 | **채택** |
| B. 월 1회 xlsx 불러오기 | 암호 걸린 케이뱅크 xlsx를 앱이 해독·파싱 | 누락 없음, 형식 안정적 | 매달 파일 전달이 귀찮음(사용자가 거절) | 보류(부록 A) |
| C. 엑셀 메모 기반 분류 | 은행 앱/엑셀에 메모를 적고 메모로 분류 | 구현 단순 | 메모 작성이 매일 일이 됨 | 기각 |
| D. 토스·뱅크샐러드 사용 | 마이데이터 자동 연동 앱 사용 | 구현 0 | 이 앱을 쓰지 않게 됨 | 사용자에게 안내만 함 |

사용자가 A를 선택했다.

## 5. 사용자가 정한 것

### 5.1 고정 카테고리 목록

사용자 추가/이름 변경/삭제 기능을 없앤다. 카테고리 관리 화면은 제거한다(순서 변경도 없음).

**지출**
| 대분류 | 소분류 |
|---|---|
| 식비 | 식사 · 카페 · 간식 · 배달 · 장보기 |
| 교통 | 대중교통 · 택시 · 주유/주차 |
| 생활 | 통신 · 공과금 · 생활용품 · 구독 |
| 쇼핑 | 의류/미용 · 온라인쇼핑 · 간편결제 충전 |
| 여가 | 문화 · 여행 · 술/모임 |
| 기타 | 의료 · 경조사/선물 · 기타 |

**수입** (대분류 "수입" 하나 아래 소분류로 둘지, 각각 대분류로 둘지는 빌더 판단): 월급 · 캐시백/이자 · 용돈 · 기타
**저축** (위와 동일): 적금 · 투자 · 연금 · 청약 · 기타 *(기타는 리뷰 후 추가 — 예금·파킹통장·비상금 등 매핑 대상이 필요해서. 작성자 판단)*

이모지 아이콘은 기존 `CategoryEntity.icon` 칸을 그대로 쓰고, 고르는 건 빌더 몫.

### 5.2 기존 데이터 이전

- 현재 `master`의 기본 트리(`AppDatabase.DEFAULT_CATEGORY_SEEDS`, 지출 대분류 16개)와 사용자가 직접 만든 카테고리를 새 목록으로 옮기는 Room 마이그레이션(v6 → v7)을 만든다.
- 거래는 지우지 않고 새 카테고리로 `category_id`를 옮긴다(반복 규칙은 5.6에 따라 제거). 예산(`category_budgets`)도 같은 규칙으로 옮기고, 같은 대상에 둘 이상 겹치면 합친다.
- 매핑 결과 "기타"로 들어가는 거래는 메모 앞에 원래 카테고리 이름을 붙인다(예: `[교육>도서] 메모`). 되돌릴 수 없는 합치기라서 흔적을 남긴다. *(작성자 판단)*
- 예산은 대분류 기준이다. 옛 대분류가 여러 새 대분류로 흩어지면, 그 대분류 소분류들이 가장 많이 가는 새 대분류로 옮기고 겹치면 합친다. *(작성자 판단)*
- 매핑표는 이름 기준으로 코드에 정의한다(예: 생활/마트>장보기 → 식비>장보기, 차량>주유 → 교통>주유/주차, 주거/공과금>* → 생활>공과금, 통신>휴대폰 → 생활>통신, 통신>구독 서비스 → 생활>구독, 의료>* → 기타>의료). 매핑에 없는 것(사용자가 만든 것 포함)은 같은 kind의 "기타" 소분류로 보낸다.
- 기존 `topUpDefaultCategories`/`categorySeedVersion` 방식(부족분 채우기)은 고정 목록과 충돌하므로 제거하거나 "고정 목록과 정확히 일치시키기"로 바꾼다.

### 5.3 알림 자동 기록 흐름

1. 설정에 "자동 기록" 섹션: 알림 접근 허용 상태 + 허용 버튼, 알림을 읽을 앱 선택(설치된 앱 목록에서 고름, 기본값은 케이뱅크 `com.kbankwith.smartbank` 등 알려진 금융 앱만 미리 체크 — 정확한 패키지명은 빌더 확인).
2. 선택된 앱의 알림만 처리한다. 다른 앱 알림은 저장하지 않는다.
3. **공통 파서**로 먼저 해석한다: 제목+본문(`EXTRA_TITLE`, `EXTRA_TEXT`, `EXTRA_BIG_TEXT`)에서 `숫자,숫자원` 금액을 찾고, 키워드로 방향을 정한다.
   - 승인/결제/출금/이체(보냄) → 출금, 입금/받음 → 입금, 취소/환불 → 환불
   - **금액을 못 찾으면** 원문 로그(5.5)에만 남기고 확인 필요에는 넣지 않는다. 은행 앱의 광고·로그인·보안 알림이 확인 필요를 채우지 않게 하기 위함. *(작성자 판단)*
   - 금액은 있는데 방향을 못 찾으면 확인 필요로 보낸다.
   - **가맹점/상대 이름 추출(최선 노력)**: 제목+본문에서 금액·날짜·시각·키워드(승인/결제/입금 등)·마스킹된 카드·계좌번호(`*`, `(1234)`)·통장 이름을 지우고 `|`·줄바꿈으로 나눈 조각 중 가장 긴 것을 이름으로 쓴다. 이름이 비면 학습 규칙을 만들지 않는다(사용자가 고른 결과만 그 거래에 적용). *(작성자 판단)*
   - 첫 릴리스는 이 휴리스틱 + 원문 로그로 시작하고, 앱별 파서는 모인 원문을 보고 추가한다.
4. **앱별 파서**가 있으면 공통 파서보다 먼저 쓴다. 현재 확인된 형식은 케이뱅크 입금 하나뿐이다:
   - 제목 `입금 1원`, 본문 `보낸사람 | 통장이름(끝4자리)` (화면에서는 잘려도 extras에는 전체가 있음).
   - 나머지 형식은 아직 모른다. 원문 로그를 쌓아 나중에 다듬는다(5.5).
5. 분류(5.4)를 거쳐 확신 있는 건 바로 거래로 등록, 아니면 "확인 필요" 목록에 넣는다.
6. 자동 등록된 거래는 메모에 가맹점/상대 이름을 넣고, 자동 기록 출처를 표시한다(목록에서 작은 표시).

### 5.4 자동 분류

우선순위 높은 것부터:
1. **사용자가 학습시킨 규칙**: 가맹점/상대 이름(정규화: 공백·괄호·(주) 제거, 소문자) → 결과. 결과는 `소분류 id` 또는 `기록 안 함`.
2. **기본 가맹점 규칙**(코드에 내장한 키워드 표): 예) 마트·편의점 → 식비>장보기, 택시 → 교통>택시, 버스·지하철·버스운송 → 교통>대중교통, 카페·커피·제과 → 식비>카페, 배달의민족·요기요·쿠팡이츠 → 식비>배달, 주유·주차 → 교통>주유/주차, 통신사 → 생활>통신, 넷플릭스·유튜브 → 생활>구독.
3. **방향 기본값**: 캐시백·이자 입금 → 수입>캐시백/이자, 환불 → 원래 지출을 줄이는 대신 수입>기타로 기록(단순화, 빌더가 더 나은 방법이 있으면 제안).
4. 그 외(사람 이름 송금, 충전, 모르는 가맹점) → **확인 필요**.

"확인 필요" 화면에서 사용자가 지출(카테고리)/수입/저축/기록 안 함을 고르면, 그 가맹점/상대 이름에 대한 규칙(1번)으로 저장하고 이후 같은 이름은 자동 처리한다. 규칙을 확인·삭제할 수 있는 간단한 목록은 설정에 둔다.

### 5.5 원문 로그

- 선택된 앱의 알림은 파싱 성공 여부와 상관없이 원문(패키지, 제목, 본문, 수신 시각)을 Room에 저장한다. 최근 90일만 보관하고 오래된 건 지운다.
- 목적: 캡처 없이 앱별 형식을 파악해 파서를 다듬는 것. 개발자가 USB 디버깅으로 기기에서 꺼내 볼 수 있으면 충분하다(앱 안에서 내보내기 기능은 만들지 않음).

### 5.6 중복 방지

- **같은 알림 재수신**: 패키지 + 알림 key/postTime + 원문 해시로 한 번만 처리한다.
- **충전 ↔ 실제 결제**: 케이뱅크 출금 중 상대가 간편결제 충전(네이버페이·페이북 등 키워드)이면 기본 분류를 "기록 안 함"으로 한다. 실제 지출은 해당 결제 앱 알림으로 기록된다. 사용자가 그 결제 앱을 알림 대상에서 빼둔 경우엔 충전을 지출>쇼핑>간편결제 충전으로 기록한다.
- **은행 + 카드사 이중 알림**: 같은 금액·같은 날·몇 분 이내 출금이 서로 다른 앱에서 오면 뒤에 온 것을 확인 필요로 보낸다(자동 삭제는 하지 않음).
- ~~캐시백 자동 추가와의 중복~~: `origin/master`에는 `kbankCardEnabled` 로직이 없다(문자열 `settings_kbank_card_*`만 남음). 남은 문자열은 지운다.
- **반복 규칙과의 중복**: 반복 거래 기능을 없앤다(사용자 결정). 실제로 나간 돈은 알림이 기록한다.
  - 반복 규칙 목록·편집 화면, 설정 진입점, `RecurringRuleWorker`의 규칙 적용, 앱 시작 시 `applyDueRecurringRules()` 호출을 제거한다. 워커가 기간 보관(`tryArchiveCompletedPeriods`)도 맡고 있으면 그 부분은 남긴다.
  - 이미 기록된 거래는 그대로 둔다. `recurring_rules` 테이블은 v7 마이그레이션에서 지우되(카테고리 이전 대상에서도 제외), 거래 메모의 자동 표시는 손대지 않는다.
- **수동 입력과의 중복**: 사용자가 손으로 넣은 거래와 같은 날·같은 금액·같은 방향의 알림이 오면 자동 등록하지 않고 "중복 같아요"로 확인 필요에 보낸다. *(작성자 판단)*

## 5.7 백업

`allowBackup="true"`이고 추출 규칙이 없어 DB 전체(거래·원문 로그 포함)가 클라우드 백업된다. 거래 자체가 이미 금융정보라 원문 로그만 따로 빼는 건 의미가 작다. 이번 범위에서는 바꾸지 않고, 원문 로그는 90일 보관으로 범위를 줄인다. *(작성자 판단)*

## 6. 빌더에게 맡기는 것

- 엔티티/테이블 이름, 패키지 구조, 파서 인터페이스 모양.
- 수입·저축을 대분류 하나로 둘지 각각 둘지(5.1).
- 이모지 선택, 확인 필요 화면 디자인(기존 토스풍/미드나잇 테마 컴포넌트 사용).
- 거래에 출처(자동/수동)와 원문 참조를 어떻게 연결할지.
- 알려진 금융 앱 패키지명 목록.

## 7. 검증

- 공통 파서·케이뱅크 입금 파서·가맹점 규칙·정규화: JVM 단위 테스트(가짜 알림 문구).
- 마이그레이션 v6 → v7: 기존 시드 + 사용자 정의 카테고리 + 거래 + 반복 규칙 + 예산이 있는 DB에서 거래 수·합계가 보존되고 반복 규칙 테이블이 사라지는지 테스트.
- 에뮬레이터에서 `adb shell cmd notification post`로 가짜 알림을 띄워 등록·확인 필요 흐름 확인.

## 부록 A. 엑셀 불러오기 조사 결과 (보류)

- 케이뱅크 내보내기 파일은 OOXML Agile 암호화(AES-128-CBC, SHA-1, spinCount 100000). `javax.crypto`만으로 해독 가능.
